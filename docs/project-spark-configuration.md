# Project Spark 配置说明

本项目只服务一个公司和一个微信公众号。生产配置保存在服务器的 `.env.production`
中，不提交到 Git。可以复制 `.env.example` 后替换占位值。

生产配置文件保存在 `/opt/spark/.env.production`，并设置为仅部署账户可读。

## 外部平台提供的信息

| 配置                | 具体含义                                                                     | 从哪里获取                    | 是否保密             |
| ------------------- | ---------------------------------------------------------------------------- | ----------------------------- | -------------------- |
| `WECHAT_APP_ID`     | 微信公众号开发者 ID，通常以 `wx` 开头；不是公众号原始 ID `gh_xxx`。          | 微信公众号后台的开发/基本配置 | 否，但只配置在服务端 |
| `WECHAT_APP_SECRET` | 与 AppID 配套的开发密钥，用于保留的 OAuth、access token 和关注状态查询能力。 | 微信公众号后台生成或重置      | 是                   |

当前生产活动使用匿名身份。Compose 始终向 API 显式传入
`ACTIVITY_IDENTITY_MODE`；未在部署环境中设置时传入
`anonymous`。不要把生产配置改成
`wechat`：该模式仅为未来具备保留 OAuth 流程能力的公众号账户预留。

当前系统不使用公众号原始 ID、微信支付商户号、EncodingAESKey 或 UnionID。

活动入口使用可分享的 HTTPS 活动链接，例如
`https://spark.gamstek.com/activity/<activityCode>`，可用于海报、群公告和客服话术。首次打开会在该浏览器建立匿名活动会话，Cookie 最长保留 7 天。匿名 Cookie 不能跨设备识别同一人：清除 Cookie、使用无痕窗口或更换设备都可能建立新的会话，因此不能依赖它限制同一人跨设备重复参与。

## 活动配置与自有表单

每个活动的模板配置包含以下运营字段：

| 字段                 | 含义                                       |
| -------------------- | ------------------------------------------ |
| `requireSubscribe`   | 保留的关注规则值；当前匿名模式不检查关注。 |
| `winningProbability` | 总中奖概率，范围 0–100，默认 0。           |
| `halfDayPrizeLimits` | 各奖项在上海时间每半天的中奖数量上限。     |
| `rulesText`          | 活动规则，必填，最多 4000 字。             |

活动页内置固定的 13 题报名表。Q1–Q12 必填，Q13 可选；两个“其他”选项被选中时必须填写对应说明。手机号校验中国大陆 11 位号码，邮箱校验地址格式；自动去除首尾空格。提交前必须同意隐私协议。

表单通过当前匿名活动会话与 CSRF 校验调用
`POST /api/activity/:code/form-submissions`。服务端在同一事务中保存答案并确认留资，首次有效提交后不能覆盖。活动页随后刷新运行状态进入抽奖；管理端提供 13 题详情及 XLSX 分列导出。

历史外部表单数据库切换到自有报名表时不迁移旧答案；该结构切换曾要求获授权运维人员手动重建数据库，再执行
`pnpm --filter @spark/api db:migrate`
创建当前结构。已经使用自有报名表的数据库可直接执行后续前向迁移，本次更新不需要清空数据。历史结构切换步骤见[部署指南](project-spark-deployment.md)。

## 抽奖、库存与图片优化

- 先按总中奖概率判断是否中奖，再以
  `min(剩余库存, 本半天上限 − 本半天已中奖数量) × 奖项权重`
  随机选择奖项。新建奖项权重默认为 1；不按列表或奖项等级顺序发奖，稀缺奖项不会和大量普通奖均分中奖机会。随机分配仍可能提前抽出大奖，并不承诺大奖在特定时间出现。
- 半天按上海时间 00:00–12:00、12:00–24:00 划分。半天上限为 0 时该奖项不参与发放；总中奖概率和各奖项上限在活动开始后仍可调整。
- 奖品操作菜单保留“添加库存”，新增“调整库存”：正数增加、负数减少，开始后仍可操作。减少数量不得超过当前可用库存，已中奖、已领取或已过期奖品均不能扣回。每次操作记录管理员和带符号的变更数量，使用 operationId 防止重试重复调整，并与抽奖共用奖品行锁。
- 本次库存调整包含前向迁移
  `1788739213000-SignedStockAdjustments`，在已有自有报名表数据库上执行
  `pnpm --filter @spark/api db:migrate` 即可，保留已有中奖和库存记录。
- 活动内置图片保留 JPG/PNG，使用 `node scripts/optimize-activity-images.mjs`
  预览压缩量，加 `--write`
  后保存；重新导入设计切图后可重新执行。二维码保留 PNG 并验证可识别性。
- 管理后台上传 JPEG、PNG、WebP 后，后端会实际解码校验，压缩时去除元信息、将超大图片限制在 1280
  ×
  1280 内，并保持原格式；记录和提供压缩后的文件。压缩后体积反而变大时保留原文件。仍执行上传前 5
  MiB 限制。
- 既有上传图片可用 `pnpm --filter @spark/api media:optimize` 预览压缩效果，加
  `--write`
  后原位压缩，文件名、格式和活动/中奖快照中的 URL 均不改变。生产容器可在
  `/app/apps/api` 下运行
  `node dist/scripts/optimize-media.js --write`，读取容器中的 `MEDIA_ROOT`
  与数据库配置；这一步需要媒体卷可写。默认预览不改文件和数据库。

## 系统自行生成的密钥

| 配置                          | 用途                                                                 | 变更影响                                                           |
| ----------------------------- | -------------------------------------------------------------------- | ------------------------------------------------------------------ |
| `CSRF_SECRET`                 | 生成活动端、管理端和工作人员端写请求的 CSRF 校验值。                 | 修改后现有页面会话需要重新登录。                                   |
| `OAUTH_STATE_SECRET`          | 签名微信公众号 OAuth 的一次性 state，防止回调伪造和重放。            | 修改时正在进行的 OAuth 会失败，用户可重新进入活动。                |
| `WECHAT_TOKEN_ENCRYPTION_KEY` | 加密 PostgreSQL 中缓存的公众号 access token。                        | 多实例和数据库恢复必须使用同一个值。                               |
| `REDEEM_CODE_ACTIVE_KEY_ID`   | 指定新兑奖码使用的密钥标签，例如 `v1`。                              | 必须能在 `REDEEM_CODE_KEYS` 中找到同名项。                         |
| `REDEEM_CODE_KEYS`            | JSON 格式的兑奖码 AES 密钥集合；每个值是 Base64 编码的 32 字节密钥。 | 轮换时新增密钥并切换 active ID；删除旧密钥会导致旧兑奖码无法展示。 |

可用 OpenSSL 生成随机值：

```bash
openssl rand -base64 32
```

三个通用签名/加密密钥分别执行一次，不能复用。兑奖码密钥把命令结果作为
`REDEEM_CODE_KEYS` 中对应 key ID 的值。

## 数据库与运行配置

| 配置                                                  | 具体含义                                                                                                                                                            |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `DATABASE_URL`                                        | API 和集成测试共用的 PostgreSQL 连接串。生产容器中的主机名为 `postgres`；执行集成测试时数据库名必须包含 `test`，否则测试会拒绝启动。密码含特殊字符时必须 URL 编码。 |
| `DATABASE_SCHEMA`                                     | PostgreSQL schema，默认 `public`。                                                                                                                                  |
| `POSTGRES_DB` / `POSTGRES_USER` / `POSTGRES_PASSWORD` | 生产 Compose 创建 PostgreSQL 容器时使用的数据库名、账号和密码。                                                                                                     |
| `MEDIA_ROOT`                                          | 活动图片保存目录，生产环境映射到持久卷。                                                                                                                            |
| `PRIVATE_EXPORT_ROOT`                                 | 私有线索导出目录，文件不会由 Nginx 公开暴露。                                                                                                                       |
| `JOB_POLL_INTERVAL_MS`                                | PostgreSQL 后台任务轮询间隔，默认 1000 毫秒。                                                                                                                       |
| `MAINTENANCE_INTERVAL_MS`                             | 过期 Session、导出等维护任务间隔，默认 3600000 毫秒。                                                                                                               |
| `ACTIVITY_IDENTITY_MODE`                              | 生产 API 接收的活动身份模式；匿名部署为 `anonymous`，Compose 未设置时也会显式传入该值。                                                                             |

## 上线前还要确定的业务数据

- 对外可分享的活动链接或二维码，以及活动页面中的参与说明。
- 活动名称、四个时间点和活动规则。
- 奖品名称、图片、初始库存、中奖概率和各奖项半天中奖数量。
- 渠道代码及各渠道二维码。
- 初始管理员账号，以及工作人员账号和活动权限。
