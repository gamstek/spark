# Project Spark 上线验收

## 自动检查

当前自动检查覆盖 API 生产任务装配、活动运行时状态计算、版本化奖项快照、兑奖过期、管理后台、报表与导出。activity、staff 页面及其 Playwright 流程按产品决定暂缓，不计入当前完成范围。

- 从空 PostgreSQL 执行全部迁移，运行 `pnpm verify`。
- 运行管理端 Playwright 测试；收到 activity、staff 设计稿并完成 T12/T13 后，再把对应端到端流程加入 CI。
- 对部署地址运行 `tests/e2e/deployment.spec.ts`，确认三个入口可深链接刷新，未知
  `/api` 路由仍返回 JSON 404。
- 运行模板兼容检查，确认数据库引用的所有模板版本均已注册。

## 外部联调

以下检查需要用户指定的测试公众号、活动及钉钉表单，未取得真实证据前保持未完成：

- [ ] 微信内静默 OAuth 能恢复活动 Session，外部浏览器有明确提示。
- [ ] 打开钉钉表单时 `participationId` 已预填并随记录保存。
- [ ] 回调携带约定请求头、`recordId` 和字段；重复回调只采纳首次有效线索。
- [ ] 返回活动页后能够抽奖；并发请求只产生一次结果且库存不超发。
- [ ] 工作人员扫码后先核对奖品，再确认发放；丢响应后查询得到原核销结果。

## 故障与现场操作

- 缺货时停止引导继续提交，后台确认库存后只能使用“添加库存”。
- 钉钉回调失败时从钉钉自动化记录重发，后台检查失败任务，禁止手工伪造客户记录。
- 相机权限被拒绝时改用兑奖码手工输入；无效、过期和已核销状态不得发奖。
- 误发实物时记录活动、兑奖码、工作人员和时间，由运营人工联系处理，不直接修改中奖记录。
- 演练重复回调、任务处理中断、数据库与媒体恢复；核对中奖、库存及核销总数不变。
