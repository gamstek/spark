# Project Spark 上线验收

## 自动检查

当前自动检查覆盖 API 生产任务装配、自有报名表事务与校验、活动运行时、版本化奖项快照、兑奖过期、管理后台参与者详情和分列导出。

- 本次结构切换必须重建空 PostgreSQL 数据库，不迁移或保留旧报名数据；执行全部迁移后运行
  `pnpm verify`。
- 运行活动表单、管理端和已实现的工作人员端 Playwright 测试。
- 对部署地址运行 `tests/e2e/deployment.spec.ts`，确认三个入口可深链接刷新，未知
  `/api` 路由仍返回 JSON 404。
- 运行模板兼容检查，确认数据库引用的所有模板版本均已注册。

## 外部联调

以下检查需要已部署的匿名活动、测试设备及工作人员账号，未取得真实证据前保持未完成。逐项用例、预期结果与执行顺序见[外部联调验收计划](project-spark-external-acceptance-plan.md)。

- [ ] API 容器收到
      `ACTIVITY_IDENTITY_MODE=anonymous`；已发布活动的分享链接可在普通浏览器和微信内打开。
- [ ] 同一浏览器的匿名活动 Cookie 最长保留 7 天；清除 Cookie、无痕窗口或更换设备会建立新会话，运营方已确认不能依赖它跨设备限制重复参与。
- [ ] 活动页内可填写固定 13 题表单；必填项、条件说明与隐私同意校验正确。
- [ ] 提交请求携带会话及 CSRF；重复提交保留首次答案，后台详情与 XLSX 列完整可读。
- [ ] 提交成功后能够抽奖；并发请求只产生一次结果且库存不超发。
- [ ] 工作人员扫码后先核对奖品，再确认发放；丢响应后查询得到原核销结果。

## 故障与现场操作

- 缺货时停止引导继续提交，后台确认库存后只能使用“添加库存”。
- 表单请求失败时保留当前填写内容并允许重试；响应丢失后重提不覆盖首次答案。导出失败时检查通用后台任务。
- 相机权限被拒绝时改用兑奖码手工输入；无效、过期和已核销状态不得发奖。
- 活动链接可用于公共二维码、群公告或客服直链；现场人员说明匿名 Cookie 只在当前浏览器最长保留 7 天，不能跨设备限制重复参与。
- 误发实物时记录活动、兑奖码、工作人员和时间，由运营人工联系处理，不直接修改中奖记录。
- 演练重复提交、表单事务回滚、导出任务处理中断、数据库与媒体恢复；核对中奖、库存及核销总数不变。
