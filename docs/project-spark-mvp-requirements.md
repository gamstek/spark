# Project Spark（火花）营销抽奖系统需求文档

> **实施规则更新（2026-09-12）**：本文保留原始业务背景。当前生产使用匿名活动会话与自有固定 13 题报名表，不提供动态字段编辑器。Q1–Q12 必填、Q13 可选；两个“其他”选项需补充说明，提交前必须同意隐私协议。
>
> 表单调用
> `POST /api/activity/:code/form-submissions`，通过活动会话及 CSRF 校验，在同一事务中保存首次答案并确认留资；重复提交不覆盖。提交成功后显示确认页，用户点击“去抽奖”再刷新运行状态。后台提供完整答案详情与 XLSX 分列导出。
>
> “100% 中奖”仅适用于 `noPrizeWeight=0`
> 且有有效奖品库存的抽奖；权重大于 0 时可能产生未中奖结果。资格不预留库存；未中奖权重为 0 且库存耗尽时不消耗资格。已开始活动锁定模板和业务规则，仅可提前结束抽奖及增加已有奖项库存；抽奖与兑奖分别截止，兑奖过期不回补库存。每个匿名会话每活动限一次中奖，清除 Cookie 或更换设备可能建立新身份。
>
> 活动配置仅包含
> `requireSubscribe`、`noPrizeWeight`、`heroAssetId`、`rulesText`，见[配置说明](project-spark-configuration.md)。初始数据库结构已重写，已有部署必须按[部署指南](project-spark-deployment.md)重建空库，不迁移或保留旧报名数据。

> **版本：V1.0 MVP**\
> **形态：微信内 H5 + 工作人员核销端 + PC 管理后台**\
> **开发周期：1 周**

## 一、项目背景

应销售同事需求和实际业务需要，开发一套用于展会、论坛、客户活动等场景的营销抽奖系统，实现公众号关注、客户意向信息收集、抽奖、现场兑奖和线索导出。

由于开发周期只有 **1 周**，V1.0
不建设完整营销活动平台，优先保证首场活动稳定上线，同时保留多活动复用能力。

> **V1.0
> 原则：保留完整业务闭环，精简动态配置、复杂库存、数据分析和平台化能力。**

## 二、系统结构

1.  **用户端 H5**
2.  **工作人员奖品核销端**
3.  **PC 管理后台**

核心流程：

``` text
进入活动 → 关注公众号 → 检测关注状态 → 填写表单
→ 获得 1 次抽奖机会 → 100% 中奖 → 生成兑奖二维码
→ 工作人员扫码 → 发放奖品 → 完成核销 → 导出客户线索
```

## 三、用户端 H5

### 3.1 用户参与流程

**扫描活动二维码**\
↓\
**进入活动并静默识别用户**\
↓\
**关注公众号并检测关注状态**\
↓\
**填写活动表单**\
↓\
**获得 1 次抽奖机会**\
↓\
**抽奖并 100% 中奖**\
↓\
**生成兑奖二维码**\
↓\
**工作人员扫码核销**\
↓\
**领取奖品**

### 3.2 无感用户身份

用户全程：

-   不注册账号
-   不输入密码
-   不授权头像昵称
-   不出现"微信登录"页面

用户首次进入 H5 时，通过微信公众号静默 OAuth 获取
`OpenID`，后台创建内部匿名用户，例如 `USER_8F38A2C...`。

内部用户用于关联：

-   微信 OpenID
-   活动与渠道
-   关注状态
-   表单
-   抽奖资格
-   中奖记录
-   兑奖码
-   核销状态

默认规则：

> **同一个用户在同一个活动中只能获得并使用 1 次抽奖机会。**

暂不支持每日多次、分享/邀请增加次数等规则。

### 3.3 活动首页

展示：

-   活动名称
-   活动主视觉 / KV
-   活动介绍
-   活动时间
-   奖品信息
-   活动规则
-   参与按钮

**V1.0 取消完整页面装修系统。**

采用统一页面模板，后台只允许维护活动名称、主图、介绍和规则。不开发拖拽装修、动态组件、模块排序、多模板和主题编辑器。

### 3.4 公众号关注

固定参与条件：

> **关注公众号 + 填写表单 = 1 次抽奖资格**

流程：

``` text
检测关注状态
↓
未关注 → 展示公众号二维码
↓
用户关注
↓
点击“我已关注，继续”
↓
后台重新检测
↓
通过 → 填写表单
```

**V1.0 不开发动态参与条件配置、多公众号和活动级公众号配置。**

## 四、活动表单

主要用于收集销售线索。

建议字段：

  字段          必填
  ------------- ------
  姓名          是
  手机号        是
  公司 / 单位   是
  职位          否
  产品兴趣      否

如现有"问卷收集表"能力可以复用，则优先复用。

V1.0 不开发完整动态表单设计器。确有需要时仅支持：

-   字段显示 / 隐藏
-   是否必填
-   简单单选 / 多选选项维护

暂不实现拖拽设计、任意字段类型、条件联动、逻辑跳转和复杂动态校验。

## 五、抽奖

用户完成公众号关注和表单提交后获得 **1 次抽奖机会**。

系统必须防止重复点击、刷新、网络重试、重复接口请求和重新进入页面造成重复抽奖。

V1.0 固定：

> **100% 中奖。**

已经抽奖的用户再次进入活动时，直接恢复原中奖结果。

## 六、奖品与奖池

每个活动可以配置多个奖品：

-   奖项
-   奖品名称
-   奖品图片
-   奖品数量
-   剩余数量

示例：

  奖项     奖品         数量
  -------- ---------- ------
  一等奖   蓝牙耳机       10
  二等奖   保温杯         50
  三等奖   雨伞          200
  参与奖   扇子          500

### 6.1 抽奖规则

V1.0 根据各奖品当前剩余数量进行加权随机。

``` text
一等奖 10
二等奖 50
三等奖 200
参与奖 500

权重 = 10 : 50 : 200 : 500
```

每次抽奖后根据剩余库存重新计算。

### 6.2 暂不实现

-   后台概率编辑器
-   大奖保护动态配置
-   大奖最小间隔
-   智能随机分布
-   奖池模拟
-   奖池预览
-   奖池版本

如首场活动必须控制大奖出现时间，采用固定业务规则或代码配置。

## 七、兑奖码

中奖后生成唯一兑奖二维码，关联：

``` text
活动 + 用户 + 中奖记录 + 奖品
```

状态：

-   待兑奖
-   已核销
-   已过期

要求兑奖码唯一、不可重复核销、核销后立即失效，并记录核销人员和时间。

## 八、工作人员核销端

### 8.1 工作人员账号

-   不开放注册
-   管理员后台创建
-   支持启用 / 停用
-   可分配允许核销的活动
-   使用 **账号 + 密码** 登录

暂不实现验证码登录、邀请码、二维码邀请和自助加入。

### 8.2 工作台

展示：

-   当前活动
-   今日核销数
-   剩余奖品
-   扫码核销入口

### 8.3 核销流程

``` text
登录 → 选择活动 → 扫描兑奖码 → 查询中奖记录
→ 展示奖品 → 确认发放 → 完成核销 → 兑奖码失效
```

记录活动、用户、奖品、工作人员和核销时间。

### 8.4 异常

只处理：

-   已核销
-   已过期
-   无效兑奖码

## 九、库存

V1.0 只维护：

-   **总库存**
-   **已中奖**
-   **已核销**
-   **剩余可抽 = 总库存 - 已中奖**
-   **待兑奖 = 已中奖 - 已核销 - 已过期**

**取消核销点库存体系。**

暂不实现核销点、仓库库存、库存分配、库存调拨和多级库存。所有工作人员共享活动库存。

## 十、PC 管理后台

V1.0 后台只解决：

1.  管理活动
2.  管理奖品
3.  管理参与用户和表单数据
4.  管理工作人员
5.  查看兑奖记录
6.  查看基础数据
7.  导出销售线索

### 10.1 最终菜单

``` text
数据总览
活动管理
奖品管理
参与用户
兑奖记录
工作人员
系统设置
```

## 十一、数据总览

展示当前活动：

  指标       说明
  ---------- ----------------
  访问人数   进入活动人数
  关注人数   已确认关注人数
  表单提交   完成留资人数
  已抽奖     完成抽奖人数
  待兑奖     中奖未领取人数
  已核销     已领奖人数
  剩余奖品   当前可抽奖品

简单展示：

``` text
访问 → 关注 → 表单 → 抽奖 → 兑奖
```

暂不实现复杂漏斗、实时动态、BI 大屏和自定义统计。

## 十二、活动管理

活动状态简化为：

-   未开始
-   进行中
-   已结束

支持创建、编辑、查看、开始和结束活动。

活动配置仅包括：

-   活动名称
-   开始 / 结束时间
-   活动介绍
-   活动主图
-   活动规则

暂不实现：

-   活动模板
-   活动复制
-   活动版本
-   暂停 / 恢复
-   复杂生命周期
-   页面装修
-   动态参与条件

## 十三、参与用户

用户列表展示：

-   姓名
-   手机号
-   公司
-   职位
-   产品兴趣
-   渠道
-   关注状态
-   表单状态
-   中奖奖品
-   兑奖状态
-   参与时间

用户详情展示表单、中奖、兑奖和核销信息。

V1.0 仅提供姓名、手机号、公司、奖品、兑奖状态等简单搜索和筛选。

## 十四、数据导出

**V1.0 必须保留。**

支持 Excel 导出：

-   姓名
-   手机号
-   公司
-   职位
-   产品兴趣
-   来源渠道
-   参与时间
-   中奖奖品
-   是否兑奖

用于销售跟进、CRM 导入和活动复盘。

## 十五、兑奖管理

后台提供：

-   **待兑奖**
-   **已核销**
-   **已过期**

已核销记录包含用户、奖品、中奖时间、核销时间和工作人员。

暂不实现邮寄管理、物流、人工延期和复杂异常处理。

## 十六、工作人员管理

支持：

-   创建账号
-   修改账号
-   重置密码
-   启用 / 停用
-   分配活动

暂不实现邀请、在线状态、复杂权限和核销点绑定。

## 十七、渠道

二维码可携带轻量渠道参数：

``` text
activityId + channel
```

例如：

``` text
ACT001 + salesA
ACT001 + salesB
ACT001 + boothA
```

后台用户列表和 Excel 展示来源渠道。

暂不开发独立渠道管理和渠道分析中心。

## 十八、系统管理

只保留：

-   管理员账号
-   工作人员账号
-   微信公众号 AppID / AppSecret / OAuth / 二维码配置

微信基础参数可以优先使用环境变量或配置文件，不强制开发后台 UI。

暂不实现 RBAC、自定义角色、操作日志中心、预警中心和系统通知。

## 十九、数据分析

V1.0 不建设完整数据分析模块，只保留：

-   首页基础数据
-   用户列表
-   兑奖记录
-   Excel 导出

渠道分析、奖品分析、时间趋势、用户画像、核销效率、自定义报表全部进入后续版本。

-   100% 中奖和库存一致性
-   中奖记录与兑奖二维码
-   工作人员登录与扫码核销
-   防重复核销

-   用户详情
-   兑奖记录
-   工作人员活动权限
-   渠道来源
-   活动主图 / 规则编辑

## 二十二、V1.0 最终定位

V1.0 不定位为：

> **高度动态配置的营销活动平台**

而定位为：

> **支持多活动复用的营销抽奖工具**

第一周只把四件核心事情做好：

**留资 → 抽奖 → 兑奖 → 导出线索**

完成 1～2 场真实活动后，再根据销售、运营和现场工作人员的反馈决定 V2.0
功能。
