# Spark Admin 双主题界面改造设计

## 目标

将 `apps/admin` 登录后的全部页面提升到与登录页一致的专业程度。改造重点是排版、配色比例、布局关系和信息层级，而不是增加装饰。保留现有业务流程、权限模型、接口、表单校验和路由行为。

## 已确认方向

采用“双区构图 + Radix Ghost 组件语言”。

- 左侧承载品牌、当前运营上下文和待处理事项。
- 右侧是连续、舒展的工作画布，避免把每个模块包进独立卡片。
- 表格使用 Radix UI Ghost 视觉：无外框、无圆角容器、无表头填充，仅通过对齐和水平分隔线建立结构。
- 页面只保留一个高强调 Solid 主操作。搜索、筛选、分页、账号入口、行操作及普通次级操作优先使用 Ghost。
- 控件保持紧凑，不使用抢夺内容注意力的大按钮。

## 主题系统

提供浅色和深色两个完整主题，两者共享布局、组件、交互和语义色映射，只切换设计令牌。

### 浅色主题

浅色主题沿用登录页的视觉基因：雾蓝、淡紫、轻粉环境色，暖白工作画布，深紫灰正文。大面积保持干净，仅在品牌区、当前运营重点和主操作使用色彩。

建议核心令牌：

- 品牌紫：`#7255D7`
- 雾蓝：`#DDECFB`
- 淡紫：`#E9E6F8`
- 轻粉：`#EBD5E7`
- 工作画布：`#FFFFFF` / `#FAF9FC`
- 主文字：`#292844`
- 次文字：`#6F6D85`
- 分隔线：低对比紫灰

### 深色主题

深色主题使用黑紫与酒红环境色。右侧工作画布、Ghost Table、文字、分隔线、悬停态和弹层必须一起深色化，不能只改变左侧区域。

建议核心令牌：

- 深色画布：`#201D21` / `#271F25`
- 深色品牌区：`#282226` / `#3C1D2D`
- 深色主文字：`#F4F0F3`
- 深色次文字：`#AAA2AA`
- 深色分隔线：`#443A42`
- 深色主操作：`#D9586D`

成功、警告、危险和信息色保持跨主题的业务含义，并满足 WCAG 2.2 AA 对比度。

## 主题行为

- 在账号菜单内提供“浅色 / 深色 / 跟随系统”选择。
- 默认跟随系统；用户选择写入本地持久化，下次访问恢复。
- 首次绘制前应用已保存主题，避免页面闪烁。
- 登录页和登录后页面共享主题状态；浅色登录页保持当前已认可的外观，深色登录页使用同一套深色令牌转换。
- 主题切换不影响路由、查询条件、表单内容或焦点位置。

## 全局布局

桌面端采用双区结构：左侧运营上下文区，右侧主工作区。左区不是传统的纯导航栏，而是组合品牌、一级导航、当前活动摘要和待处理事项。右区顶部保留紧凑的页面上下文与账号入口。

在活动列表首页，左区展示当前运营活动和待办；在活动详情页，左区切换为当前活动摘要和活动内导航；工作人员与失败任务页面使用全局导航和对应摘要。信息必须来自现有接口；若当前接口没有可靠数据，则隐藏模块或展示诚实空状态，不制造指标。

移动端低于既有导航断点后，左区收进 Radix Dialog 导航抽屉。右侧表格保持自身横向滚动，页面主体不得通过固定视口高度或隐藏溢出来强行适配。

## 排版与密度

- 延续现有 Inter、Segoe UI、Microsoft YaHei、PingFang SC 字体栈，不加载外部字体。
- 页面标题、说明、关键数据和辅助信息形成四级层次。
- 页面标题强调稳定比例与留白，不使用全大写装饰标签。
- 数据使用等宽数字特性，列内数字右对齐。
- 主内容区减少无意义的卡片内边距；表格和列表保持紧凑但满足触控与键盘可用性。
- 按钮默认使用 Radix `size="2"`；高频紧凑操作可使用 `size="1"`，唯一主操作也不超过 `size="2"`，除非登录等独立流程有明确需要。

## 组件规则

### 按钮

- 每个页面或操作组最多一个 Solid 主操作。
- 普通导航与次级操作使用 Ghost。
- 需要可见边界的次级操作才使用 Soft 或 Outline。
- 危险操作使用红色语义，在最终确认前保持低强调。
- Busy 状态不得改变按钮尺寸。

### 表格

- 数据表默认使用 Radix Table 的 Ghost 外观，不放入有边框的 Card 或 Surface。
- 表头不填充背景，只保留底部分隔线。
- 行悬停使用轻微主题色表面；整行可导航时保持语义化链接或按钮。
- 行操作使用 Ghost IconButton 或 DropdownMenu。
- 搜索、筛选、排序、分页和页大小进入 URL 查询参数；筛选后重置或校正页码。
- 提供加载、空数据、无搜索结果、失败及总数/范围状态，且不造成明显布局跳动。

### 表单

- 活动编辑页采用“配置内容 + 发布状态”主次结构。
- 说明文字与字段对齐，减少大 Card 嵌套。
- 保留现有应用级校验、错误关联、焦点处理和防重复提交。
- 保存使用次级强调，发布使用唯一主操作；危险操作与安全操作分离。

### 反馈与弹层

- 继续使用共享 FeedbackCallout、空状态、加载状态和 Radix Dialog/AlertDialog。
- Toast、内联错误、成功反馈和确认行为跨页面统一。
- 不使用浏览器原生 `alert`、`confirm` 或 `prompt`。

## 页面迁移

### 活动管理首页

采用已确认的双区构图。左侧显示当前运营重点和待办，右侧按“标题与主操作 → 核心指标 → Ghost Table”组织。若没有活动，使用同一画布内的引导型空状态。

### 活动编辑与活动详情

活动详情左侧显示活动身份、状态和子导航。右侧编辑页按业务章节分组，发布摘要保持可见但不过度悬浮。奖品、参与者、核销、报表和导出页面统一使用同一标题、工具栏、表格和状态语言。

### 工作人员与失败任务

工作人员页面使用 Ghost 目录列表，创建与编辑保留可访问 Dialog。失败任务按处理优先级和时间组织，重试保持可感知的 pending、success 和 failure 状态。

## 可访问性与响应式

- 目标为 WCAG 2.2 AA。
- 所有交互使用原生语义或 Radix 可访问原语，提供清晰名称、可见焦点、悬停、按下、禁用和忙碌状态。
- 颜色不作为唯一状态提示。
- 支持键盘操作、200% 缩放、窄屏和 `prefers-reduced-motion`。
- 滚动条在两个主题中均清晰可用，不隐藏浏览器或应用拥有的滚动区域。

## 技术边界

- CSS 变量是主题令牌的运行时权威来源；`DESIGN.md` 同步记录令牌、布局和组件契约。
- Radix Theme 根据主题状态切换 `appearance`，自定义 CSS 只负责品牌布局和必要的应用级几何。
- 优先修复或扩展共享 AppShell、PageHeader、ActivityNav、状态与反馈组件，禁止在单个页面复制主题逻辑。
- 不在此次改造中改变 API、数据库、权限、发布锁定、库存幂等或导出保留策略。
- 当前工作树包含用户的其他未提交修改；实现与提交只处理 admin 改造相关文件，不覆盖或整理无关变更。

## 验证与验收

实现完成后执行：

- Admin formatter、lint、typecheck、unit tests 和 build。
- 现有 Playwright admin 流程，并补充主题切换与持久化覆盖。
- Premium UI 静态审计与反模式搜索。
- 浏览器人工检查浅色、深色、桌面、窄屏、键盘焦点、加载、空数据、无结果、失败和弹层打开状态。
- 对比登录页、活动首页、活动编辑页和至少一个数据列表页，确认排版、导航、反馈、标签与 Ghost 组件语言一致。

验收标准是：登录前后具备统一品牌气质；浅色与深色均完整可用；数据密集页面仍清晰高效；业务行为不发生非预期变化。
